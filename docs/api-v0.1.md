# NetDisk HTTP API v0.1

本文件记录第35单元当前功能基线 不表示完整实现HTTP/1.1 不表示公网安全评估通过

服务地址 `http://127.0.0.1:8080` 每个连接只处理一个请求 响应后关闭连接

## 接口

| 方法 | 路径 | 成功 | 正文或作用 |
| --- | --- | --- | --- |
| GET HEAD | `/health` | 200 | GET返回`OK\n` HEAD只返回头部 |
| POST | `/api/files` | 201 | 原始二进制正文上传 返回固定JSON 文件ID与SHA256 |
| GET HEAD | `/api/files` | 200 | 返回分页列表和可选`next_cursor` |
| GET HEAD | `/api/files/{id}` | 200 | 返回`id name size`详情 |
| PATCH | `/api/files/{id}` | 200 | 正文必须为仅含字符串`name`的JSON |
| DELETE | `/api/files/{id}` | 204 | 删除正式对象 无正文和Content-Length |
| GET HEAD | `/api/files/{id}/content` | 200 206 416 | 支持单字节范围 GET流式下载 HEAD只返回相同头部 |

## 上传

请求正文是原始文件字节 必须使用Content-Length 当前最大65536字节 不支持Transfer-Encoding和Expect

成功响应正文固定为`{"status":"created"}` 文件ID从`X-File-Id`响应头获取 ID格式为`upload-`加六位ASCII字母数字 服务端内容摘要从`X-File-Sha256`获取 格式为64位小写十六进制SHA256

服务使用OpenSSL EVP上下文增量处理每次已经成功写入临时文件的字节 不缓存完整正文 分片边界不会改变最终摘要 完整接收并关闭文件后才完成摘要

上传先写入`data/uploads`临时文件 完整接收并关闭后取得稳定ID与摘要 第一个SQLite事务同时插入`publishing`元数据和SHA256并提交 随后通过硬链接把对象发布到`data/objects` 第二个SQLite事务只把对应`publishing`记录切换为`ready`

对象发布失败时尝试删除`publishing`记录 切换`ready`失败时保留对象与`publishing`记录供后续恢复 不删除可能已经成功提交的对象 只有第二个事务成功后才返回201

对象和SQLite不属于同一个原子事务 进程可能留下不同磁盘阶段的`publishing`记录 这些状态不会被公开读取 服务在下一次启动监听前执行恢复 元数据提交为`ready`后即使客户端未收到响应也不回滚

## 启动恢复

服务按`created_at id`顺序读取全部`publishing`记录 同时检查`data/uploads/{id}`和`data/objects/{id}`

- 只有临时普通文件且大小匹配时创建正式硬链接 删除临时名并切换`ready`
- 只有正式普通文件且大小匹配时切换`ready`
- 两个名称均存在且为同一文件的硬链接时删除临时名并切换`ready`
- 两个名称均缺失时删除`publishing`记录
- 路径类型错误 大小不符 或两个名称不是同一文件时保留证据并终止启动

每条状态变化使用独立SQLite事务 已完成记录不会在重试时重复处理 恢复过程中途失败后再次启动可继续 未实现多服务进程同时操作同一数据目录的协调

发布恢复完成后 服务按相同稳定顺序读取全部`deleting`记录

- 正式对象是大小匹配的普通文件时删除对象 再事务性删除`deleting`记录
- 正式对象已经缺失时直接事务性删除`deleting`记录
- 对象不是普通文件或大小与元数据不符时保留对象与记录并终止启动

删除恢复不扫描无元数据对象 也不删除任何`ready`对象

发布与删除恢复完成后 服务分页读取全部`ready`元数据并遍历`data/objects`执行只读一致性审计

- 报告非法元数据ID 缺失对象 大小不符和非普通`ready`路径
- 报告没有`ready`元数据的孤立普通文件和未知非普通目录项
- 数据异常只输出摘要与逐项日志 不删除对象 不修改元数据 不阻止服务监听
- SQLite查询或目录遍历失败表示审计无法完成 此时服务终止启动

未知目录项名称写入日志前会进行百分号编码 审计只比较ID 文件类型和大小 尚不验证内容摘要

完成恢复与只读审计后 服务会在监听端口前回填旧`ready`记录的SHA256

- 只处理`sha256 IS NULL`的记录 已有摘要绝不重算或覆盖
- 对象ID必须合法 打开时使用`O_NOFOLLOW` 并用`fstat`确认普通文件和元数据大小
- 以16KiB缓冲区流式读取 前后状态变化或长度变化时不写入摘要
- SQLite使用带`id state size sha256 IS NULL`条件的单条`UPDATE` 重复启动时已回填记录直接跳过
- 非法ID 缺失对象 非普通文件和大小不符只记录原因并保留`NULL` 不伪造摘要
- 数据库错误 正常文件读取错误或OpenSSL错误会中止启动 避免把不完整执行记为成功

## 元数据

列表和详情字段如下

```json
{
  "id": "upload-Abc123",
  "name": "upload-Abc123.bin",
  "size": 3
}
```

文件ID 显示名称 大小 状态 创建时间和可空SHA256保存在`data/netdisk.db` schema版本为2 v1数据库启动时在事务内增加摘要列 旧的健康`ready`对象在后续启动阶段回填 新上传直接保存规范摘要 异常旧对象保持NULL 显示名称修改通过绑定参数的预编译语句写入SQLite 服务重启后仍保留

当前文件JSON仍只返回`id name size` 创建时间与SHA256暂未公开到列表或详情接口 列表 详情和下载都只接受`ready`记录

列表接受`limit`和`cursor`两个查询参数 `limit`默认为100且范围为1至100 游标是服务端返回的不透明字符串 客户端应原样传回 不自行修改

结果按`created_at`和`id`升序排列 有后续记录时响应增加`next_cursor` 没有后续记录时省略该字段 未知参数 重复参数 非十进制limit 非法或溢出cursor返回400 当前不执行百分号解码

键集分页能避免删除已浏览记录导致后续页行号前移 但不是数据库快照 分页期间新插入且排序键早于或等于当前游标的记录不会出现在这次遍历中

名称按UTF-8字节计1至255字节 拒绝纯空格 点 双点 ASCII控制字符 DEL 斜杠和反斜杠

## 下载

下载类型固定为`application/octet-stream` 建议文件名固定为`ID.bin` 不使用显示名称构造响应头

GET先查询`ready`元数据 再以16KiB缓冲区读取和发送 未登记对象和`publishing`对象即使已存在于磁盘也返回404 文件实际大小与元数据大小不一致返回500 可下载记录缺少规范SHA256时返回500

成功响应增加`ETag: "<64位小写SHA256>"` 没有`W/`前缀 因此是按字节内容定义的强ETag 显示名称修改不改变ETag 完整与范围响应都增加`Accept-Ranges: bytes`

请求头`Range`的bytes范围单位按ASCII大小写不敏感处理 支持`bytes=start-end` `bytes=start-`和`bytes=-suffix`三种单范围形式 数字使用uint64边界检查 显式结束超过文件末尾时截到末尾 后缀长度超过文件大小时选择整个文件

合法可满足范围返回206 `Content-Range: bytes start-end/完整大小`且`Content-Length`只描述选中范围 GET先定位到start再流式发送length字节 HEAD返回相同状态和头部但不发送正文

单范围起点不小于文件大小 空文件范围和零长度后缀返回416 响应携带`Content-Range: bytes */完整大小` 规范强ETag和固定JSON错误正文 HEAD仍只返回头部 Range语法错误或重复Range字段返回400

合法多范围和未知范围单位暂不实现并忽略Range 返回完整200而不是误用416

单个`If-Range`只支持强ETag形式 服务把它与当前持久SHA256生成的`"<sha256>"`逐字节比较 完全匹配时才解析和应用Range 因此可满足范围返回206 无法满足返回416 语法错误返回400

If-Range为不同强ETag 弱ETag HTTP日期 裸摘要或其他不支持的形式时视为不匹配 服务忽略Range并返回当前完整内容200 不返回Content-Range 客户端必须只在206时追加正文 收到200时覆盖本地旧文件

Range存在时重复If-Range字段返回400 没有Range时If-Range没有条件作用

当前不解析`If-None-Match` 不支持If-Range日期比较 不提供浏览器暂停界面

### 命令行断点下载客户端

`netdisk_download [--host IPV4] [--port PORT] [--timeout-ms MILLISECONDS] FILE_ID OUTPUT_PATH`默认连接`127.0.0.1:8080` 也可选择其他数字IPv4地址和1至65535端口 客户端把未完成正文保存在同目录`OUTPUT_PATH.netdisk-part`并把强ETag保存在`OUTPUT_PATH.netdisk-etag` 非空普通临时产物与合法状态同时存在时 客户端把临时产物长度作为Range起点并把状态中的强ETag作为If-Range

`--timeout-ms`默认5000 可配置范围1至600000 同一数值限制非阻塞connect 请求发送以及响应头和正文接收的连续无进展时间 每当真实发送或接收到字节后重新计时 它不是整个大文件下载的总耗时上限

客户端只接受带单个Content-Length和规范强ETag的响应 拒绝Transfer-Encoding 重复长度 重复ETag 非法或不一致的Content-Range以及非200 206 416状态 不把错误正文写入目标文件

206必须满足响应ETag等于状态ETag Content-Range起点等于本地长度 结束位置等于完整文件末尾且范围长度等于Content-Length 才以O_APPEND追加临时产物 200必须没有Content-Range 客户端以O_TRUNC重建临时产物并在写正文前保存新ETag 最终路径不会在这一阶段被截断

临时产物长度已经等于416的`bytes */完整大小`且响应ETag仍匹配时 客户端不写错误正文而直接重试完成校验与发布 已发布最终文件已经完整时则直接校验最终文件 完整接收或416完成路径都流式计算完整文件SHA256并与ETag比较 校验失败删除状态文件使下次运行不再发送Range

网络在正文完成前断开或超时时客户端返回非零但只改变临时产物并保留ETag 旧最终文件保持不变 下次运行从临时产物长度继续 完整SHA256匹配后使用同目录POSIX `rename`原子替换最终路径 因此同一文件系统中的路径观察者只会看到旧版本或完整新版本 不会看到下载中的前缀

状态文件在成功后仍保留 用于重复执行时通过416识别已完成文件 若上次已完成校验但`rename`失败 完整临时产物也会保留 下一次可通过416重新校验并重试公开 第33至34单元遗留在最终路径中的可续传前缀会先复制到临时产物后再追加 完成后同样原子替换

`rename`的名称切换原子性不等于断电持久性 当前未对文件或父目录执行`fsync` 路径在摘要校验和替换之间被其他本地进程恶意修改的竞争也不在当前威胁模型内 客户端仍不支持DNS主机名 IPv6 TLS或并行分块

## 删除

DELETE先确认正式对象是普通文件且大小匹配 第一个SQLite事务把`ready`切换为`deleting` 然后移除对象文件 第二个SQLite事务删除`deleting`元数据 成功返回204 无Content-Length Transfer-Encoding或正文

`deleting`不会被列表 详情或下载读取 因此第一个事务提交后新的请求立即看到404 重复删除也返回404 进程在后两步之间退出时 服务下次启动继续完成删除

当前没有回收站 文件删除与数据库事务仍不是跨资源原子操作 `deleting`只提供进程重启恢复 没有文件和目录`fsync` 不保证断电持久化

## 主要错误

| 状态 | 含义 |
| --- | --- |
| 400 | 请求格式 正文策略 ID或名称非法 |
| 404 | 路由或合法ID对应文件不存在 |
| 405 | 方法已实现但不允许用于该资源 响应包含Allow |
| 413 | 请求正文超过65536字节 |
| 416 | 单字节范围语法有效但当前表示无法满足 |
| 417 | 不支持Expect |
| 500 | 文件系统或内部处理失败 |
| 501 | 方法或Transfer-Encoding未实现 |

错误正文是固定JSON 不返回内部磁盘路径

## 第一版限制

- 串行阻塞 一次只处理一个客户端
- 服务端无读写超时 连接数限制和优雅退出 命令行下载客户端已有有限无进展等待
- SQLite元数据 发布与删除状态事务 启动恢复 键集分页 只读一致性审计 新上传SHA256 旧对象回填 下载强ETag 单Range与强ETag If-Range已实现 仍无定期内容重算比对 其他条件请求和HTTP创建时间字段
- 无用户 权限 文件夹 分享 配额 回收站和版本历史
- 无多Range与If-Range日期判断 上传续传 并行上传和秒传
- 只监听回环地址 没有TLS 不用于公网
